# ovannot: a testbed for automatic image annotation on out-of-distribution data

`ovannot` compares pipelines that annotate images automatically, with open-vocabulary models
served locally, on datasets that are unlike internet pre-training data (medical, industrial,
aerial, documents...). It covers two tasks:

- **Task 1, classification.** Given the classes of interest, give each image one class, or
  "none" when it shows none of them.
- **Task 2, detection.** Given the classes of interest (names, optionally descriptions and a
  few annotated examples), find every instance in every image: a box with a score, optionally
  a mask.

Pipelines are measured first on public benchmarks with their official protocols (RF100-VL for
detection; ELEVATER with an open-set split for classification, see
[decision D9](docs/decisions.md)), then on proprietary datasets. The repository is built so
that pipelines can be compared at a glance, a new one can be added without touching the
others, and each one can be understood from its README without reading its code.

The full specification is [docs/BRIEF.md](docs/BRIEF.md); the choices made since are logged in
[docs/decisions.md](docs/decisions.md).

## Quickstart

Requires [uv](https://docs.astral.sh/uv/) and Linux (x86_64 or aarch64).

```bash
uv sync                                        # create .venv with the pinned dependencies
uv run pytest                                  # tests that need neither GPU nor network
uv run ruff check . && uv run ruff format --check .
uv run python papers/download_papers.py        # fetch and check the papers (git-ignored)
scripts/setup_mermaid.sh                       # optional: mermaid-cli, to edit diagrams
uv run python scripts/render_diagrams.py       # re-render changed pipeline diagrams
```

Run a pipeline with
`uv run python scripts/run.py --exp configs/experiments/<name>.yaml [--subset dev|test]`, on a
node where its models are served; on the cluster, `scripts/slurm/run_experiment.sbatch` serves
them and runs it (see [serving/](serving/)). Then `uv run python scripts/make_leaderboard.py`.

## Reading the leaderboard

[`results/leaderboard.md`](results/leaderboard.md) is generated by `scripts/make_leaderboard.py`
from versioned runs, never edited by hand. It has one row per pipeline and dataset (first runs
at M3).

- **Setting.** `zero_shot` runs see class names only. `few_shot` runs also see the annotator
  instructions and the official examples (decision D4). Never compare rows with different
  settings without saying so.
- **mAP and AP50.** These follow the official RF100-VL protocol: pycocotools with up to 500
  detections per image, each dataset scored on its own, then averaged per domain and overall.
- **Precision, recall and F1 at IoU 0.5.** Measured at the pipeline's operating threshold,
  which is tuned on the dev split only.
- **Cost.** Mean and p95 time per image, MLLM calls per image, and the share of images with a
  recorded failure.
- **Dev vs test.** Dev numbers serve iteration. Test numbers are reported once per final
  pipeline, over all datasets and over the datasets never used for tuning (decision D3).

## Data and confidentiality

Datasets, model weights, caches and run outputs never enter git. `data/` is a symlink to the
cluster storage, and only `metrics.json` and the resolved config of each run are versioned.
Proprietary datasets are processed by local models only, and everything about them (loaders'
outputs, runs, concept cards, reports) lives in folders whose name ends with `_private`, which
git ignores.
